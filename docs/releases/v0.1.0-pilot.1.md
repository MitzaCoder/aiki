# Aiki v0.1.0-pilot.1

An early, assisted pilot for a few friends: run coding agents on your own computer,
then follow their work in a browser or the Android app. Use your own repositories
and provider accounts. A paired device has full backend access, including shell,
files and provider spending; this is not a sandbox or a shared hosting service.

- **Linux is the tested host path.** macOS and Windows through WSL are experimental.
- Install Git/jj and the prerequisites in [INSTALL.md](../INSTALL.md). Download and
  inspect this release's `install.sh`, then run
  `sh install.sh --version v0.1.0-pilot.1 --no-service`.
  Start with `aiki start`; in another terminal use `aiki open`, then `aiki pair`.
  Keep the one-time pairing URL/code private. Set up your provider and project.
- Android needs Android 12+ and **your own backend reachable over HTTPS**, for
  example with assisted Tailscale Serve. The computer must stay awake. The APK
  does not supply a tunnel; keep backend authentication on. Use a fresh device
  pairing link from the paired browser, then approve the matching code there.
- **No phone push notifications in this pilot.** No Google account or Firebase
  setup is required for ordinary use. Foreground connections still work.
- The APK is signed for `io.github.mitzacoder.aiki`. Check its checksum and the
  certificate fingerprint in `RELEASE-MANIFEST.json` against the owner's invitation.
  Settings → About and licences contains the dependency notices and source pointers.
- Before updating, stop the backend and back up state/config and repositories.
  Install APK updates over the existing app; do not uninstall first. The public
  key/package is not automatically compatible with an older private/debug install.
  Code rollback does not undo data migrations.

Use the **exact prerelease tag** in download links and update commands:
`aiki update --version v0.1.0-pilot.1`. `/releases/latest` and unqualified updates
select stable releases, not this pilot. Expect rough edges. Send only redacted
symptoms and version details, never credentials, pairing links or session data.
