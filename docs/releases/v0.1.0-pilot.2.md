# Aiki v0.1.0-pilot.2

An early, assisted pilot: run coding agents on your own computer, then follow their
work in a browser or Android. Use your own repositories and provider accounts.
A paired device has full backend access, including shell, files and provider
spending. This is not a sandbox or a shared hosting service.

## What's new since pilot.1

- Text files now open when the installed app uses `localhost` and its backend uses
  `127.0.0.1` (or the other way around). Failed reads offer a retry.
- An **Update available** notice and Settings → About link to release notes.
  Installed backends check about once a day; checks can be turned off. Updates
  stay manual. The saved pilot channel includes later pilot releases.
- A single executable for Linux x64/arm64 and macOS arm64. Matching installs need
  no Bun or JavaScript dependencies. The private, pinned Bun fallback remains.
- Attach files to chat on web and Android, including Android sharing. PDFs supply
  extracted text, not scanned-page OCR.
- Connect MCP servers, including Notion and remote servers. Choose tool policies
  and enable them separately for coordinator, workers and background work. Servers
  start off; sign-in and available tools depend on the server.
- Anthropic limit reset details, with explicit confirmation before a free reset.
- Task reports now show freshness and an automatic Now line. Timelines group by
  hour; project delivery settings can follow an integration branch and deploy feed.

## Install or update

See the [install guide](https://github.com/MitzaCoder/aiki/blob/v0.1.0-pilot.2/docs/INSTALL.md)
for prerequisites and reviewed download steps.
The short install command is:

```sh
curl -fsSL https://aikilabs.dev/install.sh | sh
```

This runs a checksum-verifying bootstrap pinned to this pilot. Download and read
it first if you prefer. The direct GitHub release URLs remain valid:

```sh
curl -fL https://github.com/MitzaCoder/aiki/releases/download/v0.1.0-pilot.2/install.sh -o install.sh
# Read install.sh before running it.
sh install.sh --version v0.1.0-pilot.2 --no-service
aiki start
```

In another terminal, run `aiki open`, then `aiki pair`. Keep the one-time pairing
URL/code private; connect a provider and choose a project.

**From pilot.1:** stop Aiki and back up state/config and repositories, then run:

```sh
aiki update --version v0.1.0-pilot.2
aiki start
```

That one exact-version update gives the old updater pilot-channel support. It may
use Bun for this first update. Later updates are simply **`aiki update`**, while
stopped; restart afterward. Nothing updates or restarts automatically. A code
rollback does not undo database migrations. `/releases/latest` excludes pilots.

**Android:** install the new APK over the old one; do not uninstall. It uses the
same owner signing key and package `io.github.mitzacoder.aiki`, versionName
`0.1.0-pilot.2`, versionCode **1000002** (pilot.1 was 1000001). Check its checksum
and the certificate fingerprint in `RELEASE-MANIFEST.json` against the owner's
invitation. Private/debug installations may have a different key. Settings →
About and licences has dependency notices and source pointers.

## Known limits

- Linux is the tested host path. macOS and Windows through WSL are experimental.
  Linux binaries require glibc; macOS x64 and Linux musl use the Bun fallback.
  macOS binaries are not signed/notarized.
- Android needs Android 12+, your own backend reachable over HTTPS and a computer
  that stays awake. The APK supplies no tunnel. Keep authentication on and approve
  the matching pairing code in an already paired browser.
- No phone push notifications in this pilot. No Google account or Firebase setup
  is needed for ordinary foreground use.
- MCP tools run with your backend's authority. Review permissions and approval
  arguments. OAuth needs a correctly configured callback origin; Android offers
  paste-callback recovery if the browser does not return to the app.
- PDF extraction is text-only and bounded; encrypted, scanned or malformed files
  may provide little or no text. Provider subscription eligibility still applies;
  a saved credential does not prove inference works.

Expect rough edges. Send redacted symptoms and version details, never credentials,
pairing links or session data. The owner adds exact source/APK/certificate details
to the draft's `RELEASE-NOTES.md` before publication.
